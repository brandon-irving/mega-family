# Gate G8 · Widgets, QR invite scan, homework viewfinder, invite Paste

The contract is CONTRACT.md v0.18 (pending approval) plus `shared/` (API map: `widgets.next` and the `WidgetTimeline` shapes; config `WIDGET_TIMELINE` in `widgets.ts`, `INVITE_SCAN` in `auth.ts`, `HOMEWORK.capture` in `kids.ts`, `G8_COPY`). Same process as every gate (STATUS.md → How we work): checks green, three fresh reviewers (security/privacy, correctness, UX against the boards), a failing-first test for every fix, commit locally, tag `g8`.

**This gate is mostly app work.** The backend adds one query (`widgets.next`); the QR scan feeds the existing `invites.preview` / `invites.redeem`, the viewfinder feeds the existing `files.uploadUrl` → `homework.submit`, and Paste is client only.

**Native packages are frozen (STATUS.md, Oct 28): G8 adds none.** Everything G8 uses was in `package.json` at `8e68bee`, the commit EAS dev build **`cd4140e3`** was built from: `expo-widgets ~58.0.24` (plugin configured from `shared/config/widgets.ts`, App Group `group.com.megafamily.app`), `@expo/ui ~58.0.23` (the SwiftUI components widgets are drawn with), `expo-camera ~58.0.13` (plugin with `barcodeScannerEnabled: true`, camera permission text), `expo-clipboard ~58.0.4`, `expo-image-picker ~58.0.10` (the "Choose a photo instead" fallback). Widget **kinds** are fixed: `MegaNext` (systemSmall, systemMedium, accessoryRectangular) and `MegaTalk` (accessoryCircular); don't rename or add kinds or families.

## Providers (current docs, fetched Oct 29)
- **expo-widgets SDK 58** (docs.expo.dev/versions/v58.0.0/sdk/widgets.md; not in Expo Go, dev builds only; iOS and Android, Android opt-in):
  - `createWidget(name, Component, initialProps)` returns a `Widget` with `updateSnapshot(props)` (one entry, shown now), `updateTimeline(entries: { date: Date, props }[])` (iOS only; the system switches entries at their dates), `getTimeline()`, `reload()`.
  - The component must start with the `'widget'` directive. It runs in an isolated runtime inside the widget extension: **only `@expo/ui/swift-ui` components and modifiers; no hooks, no state, no async, no imports used at runtime, no module-scope constants** (the bundler serializes only the function body). Every helper (time math, copy, colors) is declared inside the function or passed in through props.
  - The second argument is `environment: WidgetEnvironment`: `widgetFamily`, `date` (the entry's date), `widgetRenderingMode` (`fullColor` home screen, `vibrant` lock screen, `accented` tinted), `isLuminanceReduced`, `showsWidgetLabel`, `colorScheme`, `widgetContentMargins`.
  - Taps: `@expo/ui/swift-ui/modifiers` exports `widgetURL(url)` (one per widget view tree) and a `Link` component. Interactive `Button` `onPress` returns new props (iOS 17+); `addUserInteractionListener` only fires while the app runs. We don't need interactive buttons: every tap is a deep link.
  - Images must be written to `widgetsDirectory` (App Group container) and referenced by path. The pixel MEGA can instead be drawn from props (see frontend task 1).
  - Kinds and families are baked in at build time (config plugin → prebuild → rebuild). Layout and props are JS.
- **expo-camera SDK 58** (docs.expo.dev/versions/v58.0.0/sdk/camera.md):
  - `CameraView` with `barcodeScannerSettings={{ barcodeTypes: ['qr'] }}` and `onBarcodeScanned({ type, data })` (iOS, Android, web). There's also a modal `CameraView.launchScanner()` (iOS 16+ DataScanner); the LoginScan board is an in-app viewfinder, so use `CameraView`.
  - `useCameraPermissions()` → `[permission, requestPermission]`.
  - `ref.takePictureAsync({ quality, exif, shutterSound, skipProcessing })` → `{ uri, width, height, format }` (on web `uri` is base64).
- **expo-clipboard SDK 58** (docs.expo.dev/versions/v58.0.0/sdk/clipboard.md):
  - `ClipboardPasteButton` shows Apple's `UIPasteControl`, which pastes **without the iOS "Allow Paste" prompt**. Render it only when `Clipboard.isPasteButtonAvailable` (iOS 16+). Its label and icon can't be changed; set the colors with `backgroundColor` / `foregroundColor` (not `style`), give it a width and height, and pass `acceptedContentTypes` (`plain-text`, `url`). `onPress` receives the pasted payload.
  - Fallback: `Clipboard.getStringAsync()`. On iOS 16+ it shows the system prompt, and a denial returns `''`, indistinguishable from an empty clipboard. On web it asks for clipboard permission.

## Decisions (contract step, Oct 29)
1. **A new `widgets.next`, not a change to `widgets.timeline`.** The board's medium widget lists up to three items at once, and the timeline must stay right for hours without the app, so each entry carries a list plus absolute `startsAt` (the widget computes "in 40 min" from its entry date). `widgets.timeline` (G3) keeps serving its current callers.
2. **Widgets refresh only while the app runs.** No background-refresh module (`expo-background-task`) is in the frozen build. So the server plans `WIDGET_TIMELINE.horizonHours` ahead, ending on an honest `stale` entry ("Open Teal for what's next"). Adding `expo-background-task` is a post-gates candidate (STATUS native-packages note).
3. **Lock screen privacy.** A `private` item (the viewer's own private-layer event) shows `G8_COPY.widgetPrivate` instead of its title on the lock-screen families (`environment.widgetRenderingMode === 'vibrant'` or `widgetFamily` `accessory*`), and the title view gets the `privacySensitive()` modifier everywhere, so iOS redacts it while locked.
4. **No `accessoryInline`.** The Widgets board draws an inline date line, but that family isn't in the build. It ships after a rebuild; for now the lock screen has the rectangular and circular widgets.
5. **The scanner is strict.** It accepts only `mega://join/<token>` or a bare token matching `INVITE_SCAN.tokenPattern` (48 lowercase hex characters). Anything else shows `G8_COPY.scanNotInvite` and is never opened, followed or sent anywhere. `shared/inviteToken.ts` stays lenient for the paste box (people paste whatever they have); the server's `invites.preview` is the real check either way.
6. **Camera and scan are native only.** On web the invite screen keeps the LoginInviteHelp card (no scan) and the homework sheet keeps the image picker; Paste on web uses `getStringAsync`.
7. **The homework photo goes only to the upload.** `takePictureAsync` with `HOMEWORK.capture` (`exif: false`, so no GPS); nothing is saved to the camera roll; the temp file stays in the app's cache, which the OS manages (no `expo-file-system` import: it isn't a direct dependency). The existing homework rules are unchanged: only grown-ups see the photo, and the server checks role, size and type.

## Invariants (each one gets a test)
1. **A widget shows only what the viewer sees in the app.** `widgets.next` for Partner never contains Admin's private dentist, even though Partner is in Thursday's household events. For Admin it does, with `private: true`. For Twin 1 it contains only events Twin 1 is in or whole-family ones, never a gift idea, a price drop or an adult's private item, and statements only from Zap. Privacy-grid row: another family → NOT_FOUND / empty; a kid sees only their own timeline.
2. **No private title on the lock screen.** Rendering `MegaNext` with a `private` item in a lock-screen environment (`accessoryRectangular`, `vibrant`) shows `G8_COPY.widgetPrivate`, not the title, and the title view carries `privacySensitive`. Home-screen families show the title, still with `privacySensitive`.
3. **Sign-out clears the widget.** After sign-out or an account switch, the app writes the signed-out snapshot (`G8_COPY.widgetSignedOut`, no events, no statement) before anything else. Test: mocked `expo-widgets`; Admin's timeline then sign-out → the last write has no personal data.
4. **The timeline stays honest.** Entries are sorted by `at`, at most `maxEntries`, the first is at or before `generatedAt`, every `soon` item starts within `soonWindowMinutes` of its entry's `at` (or started less than `startedGraceMinutes` before it), at most `maxSoon` items per entry, and the last entry is `stale` (or `empty` when nothing is planned). No `Date.now()` on the server: the Clock port. Test against the seeded Thursday and the demo clock.
5. **The scanner only accepts invites.** Each `SCAN_GOOD` input (src/test/g8Fixtures.ts) navigates to the join route with the token; each `SCAN_BAD` input shows `scanNotInvite` and calls nothing (no `Linking.openURL`, no router push, no network). One good read during `INVITE_SCAN.cooldownMs` navigates exactly once.
6. **Camera denial is honest.** Scan with permission denied → `G8_COPY.scanDenied` with Open Settings and "Paste a link instead" (no blank camera). Homework with permission denied → the existing `KIDS_COPY.cameraDenied` and "Choose a photo instead". A camera that fails to mount (`onMountError`) → `viewfinderFailed` and the picker.
7. **The photo goes only to the upload.** `takePictureAsync` is called with `HOMEWORK.capture` (`exif: false`); no media-library or camera-roll call exists in the flow; adults only (the camera button isn't offered to kids, and the server re-checks).
8. **Paste only on a tap.** The clipboard is read only inside a Paste press (`ClipboardPasteButton.onPress` or the fallback button), never on mount or focus. Empty → `pasteNothing`; not an invite → `pasteNotInvite` (the field keeps what the person typed); an invite → the field fills and Continue works.
9. **Fail soft off-device.** On web and in tests, importing the widget module never throws; widget writes are no-ops when `Platform.OS !== 'ios'`.
10. **No stubs, no skips.** `widgets.next` is `real`; the privacy grid has zero skips.

## Backend tasks (`convex/`)
1. **`widgets.next`** (`convex/widgets.ts`, replacing the stub body):
   - Events: for an adult, the same set `family.comingUp` / `upcomingEvents` uses, but over `horizonHours`; for a kid, only events whose `who` includes them or that are for the whole family. Never another member's private-layer event, even with the viewer in `who`.
   - Mark `private` for the viewer's own `scope: 'personal'` events. `timeLabel` in the family's time zone (`shared/time.ts`, e.g. "4:00 PM").
   - Build the entries: the first at `now`; a new entry whenever the next-2-hours set changes (an event enters the window at `start − soonWindowMinutes`, or leaves at `start + startedGraceMinutes`); `maxSoon` per entry; `soon` when the set has events, else `statement` (the viewer's own MEGA's top statement, `short` cut at `shortStatementChars`), else `empty`; stop at `horizonHours` or `maxEntries − 1`, then one `stale` entry. Links: `soon`/`empty`/`stale` → `LINKS.today()`, `statement` → `LINKS.chat()`.
   - `who` names and colors like `widgets.timeline` does. Clock port only.
2. **Tests** for invariants 1 and 4, and privacy-grid rows (another family, a kid, Partner vs Admin's private event).
3. **Live check** (spend cap **$0.10**; this gate makes no model calls, so expect $0): deploy to colorless-ibis-289, `seed:resetDemo`, call `widgets.next` as Admin, Partner and Twin 1 at the seeded Thursday afternoon (clock jump) and in the evening; report the entries.
