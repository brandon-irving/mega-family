# Gate G4 · Web search (kid filter), weather + NWS alerts, travel time

The contract is CONTRACT.md v0.15 (pending approval) plus `shared/` (tables, API map, config) and the four new ports in `convex/ports/`. Backend owns `convex/`, frontend owns `src/`; they meet only at the contract. Same process as every gate (STATUS.md → How we work): checks green, three fresh reviewers (security/privacy, correctness, UX), a failing-first test for every fix, commit locally, tag `g4`.

**Native packages are frozen (STATUS.md, Oct 28): G4 adds none.** Places are typed addresses, geocoded on the server; nothing uses the phone's location.

**Providers (current docs, Oct 28):**
- **Web search:** Meta search grounding — `tools: [{ type: "web_search" }]` on **`POST /v1/responses`** only (not Chat Completions), model `muse-spark-1.3` (`MODELS.webSearch`). Options: `search_context_size` and an approximate `user_location`. Sources: `include: ["web_search_call.results"]` (each `{ type: "text_result", title, url }`) plus `url_citation` annotations; drop `phase: "commentary"` interim messages (STATUS lessons). No safe-search and no domain filter on the Responses API, so the kid filter is entirely ours. Don't name a function tool `browser.search` / `browser.open` / `browser.find` (reserved, HTTP 400).
- **Weather:** Open-Meteo `GET /v1/forecast?latitude&longitude&hourly=temperature_2m,precipitation_probability,weather_code&daily=…&timezone=<family tz>&temperature_unit=fahrenheit&forecast_days=2` (free, no key). NWS `GET https://api.weather.gov/alerts/active?point={lat},{lng}` with `Accept: application/geo+json` and a **User-Agent** (`WEATHER.userAgent`); `properties.severity` ∈ Extreme/Severe/Moderate/Minor/Unknown. Probed live Oct 28: 200, empty FeatureCollection for Central Park.
- **Travel:** Mapbox Directions v5 `mapbox/driving-traffic`, `depart_at` (ISO) or `depart_at=now`; read `routes[0].duration` (s), `duration_typical`, `distance` (m).
- **Geocoding:** Mapbox Geocoding v6 `/search/geocode/v6/forward?q=…&country=us&limit=1&permanent=true` — **`permanent=true` because we store coordinates** (temporary results may not be cached; permanent needs a card on the Mapbox account — owner action below).

**Models:** Muse Spark only. The search call (`MODELS.webSearch`), the kid query check and answer check (`MODELS.judge`, structured output), and the agent loop (`MODELS.chat`). No Muse Wonder in G4.

## Invariants (each one gets a test)
1. **Search results are untrusted.** A `web_search` result can inform the answer text but never causes a tool call, a memory save or a cross-member action by itself (same rule as homework images). Prompt-injection test: a fake result containing "call lists_add…" changes no data.
2. **Search queries carry nothing private about anyone else.** The agent builds a query only from what the asker can see (existing context rules); the `WebSearch` request carries no profile, no member names other than the asker's own words, and `approximateLocation` is city-level only. Test: a fake WebSearch records every request; a search run in Admin's thread never contains Partner's personal memory text or Admin's private event titles from another member's context.
3. **Kid filter runs every time for kids, and rules only tighten.** For a kid: keyword backstop (`rule:kidSearchKeyword`, can only block) → model query check (allowed / rephrase / blocked) → search → answer check (age band, categories) → blocked-domain citations removed → at most `KID_SAFETY.search.maxSources`; no sources left = no answer (blocked card). `kidControls.webSearch: false` → the tool isn't offered and a forced call returns the blocked card. Homework mode: homework-answer searches get hints (`homeworkHints`). Every outcome writes a `searchLog` row with `decidedBy`.
4. **Parents see blocked searches only as configured.** `search.log` for a kid: own rows for the kid; a parent gets only `blocked`/`rephrased` rows and only when that kid's `tellsParents.blockedSearches` is on; a sibling or the other family → FORBIDDEN / NOT_FOUND. Blocked/rephrased searches notify parents per `tellsParents` (a quiet `update`, through the normal pipeline).
5. **Places are household data; adults edit.** `places.list` for any member; `places.upsert`/`.remove` FORBIDDEN for kids; at most one `home`; limits from `PLACES`.
6. **Travel follows event visibility.** `travel.forEvent` on a private-layer event is NOT_FOUND for everyone but its owner; leave-by reminders for a private event go only to its owner; for a household event, only to members in `who` who are adults (kids aren't told to drive).
7. **Fail closed, never made up.** Missing `MAPBOX_TOKEN` / provider error / no route → `failure` on the card/view and INTEGRATION_COPY text; never invented minutes, temperatures or alerts. Real mode never uses a fake adapter (`unconfiguredIntegrations.ts` until the real ones land; deleted at gate end).
8. **Alerts don't spam.** One candidate per (NWS alert id × recipient) via `dedupeKey`; Extreme/Severe push (timeSensitive), Moderate is a quiet update, Minor/Unknown dropped; kids' quiet hours still hold (an alert for a kid is held unless Extreme — config, default: held like everything else; the adults get it).
9. **No stubs, no skips.** Every v0.15 function `real`; the privacy grid probes all of them (the seed fills `places`; add `travelChecks` and `searchLog` rows to the seed so `search.log`/`travel.forEvent` have data).

## Backend tasks (`convex/`)
1. **Adapters** (`convex/adapters/`), each with unit tests against recorded fixtures (no network in tests): `metaWebSearch.ts` (Responses API via `fetch`, same auth/env as `metaChatModel`, timeout `WEB_SEARCH.timeoutMs`, usage → spend guard incl. `PRICING.webSearch` per search), `openMeteoNwsWeather.ts`, `mapboxDirections.ts`, `mapboxGeocoder.ts` (both `not_configured` without `MAPBOX_TOKEN`; never log the token). Register them in `registry.ts` for real mode; delete `unconfiguredIntegrations.ts`.
2. **Places:** `places.list/upsert/remove` (real), geocoding in an internal action scheduled on upsert (status pending → ok/failed/not_configured; retry per `GEOCODING.retryAfterHours`); `events.create/update` accept and validate `placeId` (same family); the agent's `events_create/update` tools can name a place by label. Link seeded soccer/pickup events to the "Soccer field" place and school drop-off to "School".
3. **Agent tools** (`convex/agent/toolSpecs.ts`, flip `implemented: true`): `web_search { query }`, `weather { place?, when? }` (place label; default home), `travel_time { to, from?, departAt? }` (place label or an event the caller can see). Tool results go into the reply plus a `search` / `weather` / `travel` card in the caller's thread. `WEB_SEARCH.maxPerReply`, per-member daily caps (`maxPerMemberPerDay`). Kids: tools per `ROLES_CONFIG` (kids have `web_search` and `weather`, not `travel_time`).
4. **Kid filter** (`convex/model/kidSearch.ts`): the steps in invariant 3, structured Muse Spark calls (reasoning effort low, `LIMITS.agent.maxTokensStructured`), `decidedBy` on every outcome, `searchLog` rows, parents' notice per `tellsParents`. Adults: one search call, `searchLog` row `answered`/`failed`.
5. **Weather:** `weather.get` (from cache → `WeatherView`; WMO code → short summary text in config), `weather.refresh` (TTL-gated), a cron every `WEATHER.alertsPollMinutes` refreshing alerts for each family's home and places with events today. New alerts → `weatherAlert` candidates (severity rules, dedupe by alert id); events within `eventLookaheadHours` whose start hour has precip ≥ `eventRainThresholdPct` → `weatherEvent` tip candidates ("Rain at pickup — grab umbrellas"). Write the `weather.alert` familyEvent.
6. **Leave-by:** for events with a geocoded `placeId` within `TRAVEL.lookaheadHours`: origin = `TRAVEL.defaultFrom` (home), check Directions (`depart_at` = start − typical estimate; recheck every `recheckMinutes`), store `travelChecks`, `leaveBy = start − minutes − leaveByBufferMinutes`; skip trips under `minTripMinutes`. A `leaveBy` candidate (kind `reminder`, buttons `reminder.default`) is delivered `remindBeforeMinutes` before leave-by to the adults in `who` (owner only for private events). Tighten `candidateStillApplies` for `leaveBy` (latest check still current) and `weatherAlert` (alert still active). `travel.forEvent` (visibility first).
7. **Gift ideas:** use `WebSearch` for real product ideas (GD left this to G4) through the adult path; still only household-shared facts in the query.
8. **Seed:** link events to places (task 2), one `searchLog` row per kid (one `blocked`), one `travelChecks` row for Thursday's soccer pickup, a `weatherCache` forecast for home so `weather.get` has data without network.
9. **Privacy grid rows** for `places`, `travelChecks`, `searchLog` (within-family: a sibling can't read a kid's search log; a private event's travel check is invisible to non-owners).
10. **Evals:** add ~20 synthetic labeled kid queries to the eval set (allowed / rephrase / block, incl. homework-answer and borderline cases) and commit results with precision/recall, like GD's privacy-gate eval. Count against the spend cap.
11. **Live check** (spend cap **$0.30** Meta; `MEGA_MODEL_ADAPTER=real`, deployed to colorless-ibis-289, re-seed with `seed:resetDemo`): an adult search with sources; a kid search allowed, one rephrased, one blocked (parent notified per controls); `weather.get` for home (real Open-Meteo/NWS); with MAPBOX_TOKEN: geocode a new place and a leave-by for Thursday's pickup; without it: the `not_configured` travel card.
