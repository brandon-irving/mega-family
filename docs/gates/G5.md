# Gate G5 · Onboarding chat, Gmail + calendars + schedule links, Settings, HQ, nightly profiler

The contract is CONTRACT.md v0.17 (pending approval) plus `shared/` (ids, tables, API map, config `google.ts` / `onboarding.ts`, `G5_COPY`) and the four new ports in `convex/ports/` (`googleOAuth.ts`, `mailSource.ts`, `calendarSource.ts`, `icsFetcher.ts`). Backend owns `convex/`, frontend owns `src/`; they meet only at the contract. Same process as every gate (STATUS.md → How we work): checks green, three fresh reviewers (security/privacy, correctness, UX), a failing-first test for every fix, commit locally, tag `g5`.

**Owner flow (Oct 28, canvas Screen 13):** sign up → the chat opens with the admin's MEGA (default look; tap the badge to customize) → "What should I call you?" → integration cards one at a time, **Gmail first**, then a calendar (Google Calendar or this phone's), then schedule links (.ics) → "Who should I add first?" → family steps (Screen 5 boards). Every card has Not now; skipping never blocks; Settings offers each later. Everything found lands in the owner's **private** layer; MEGA may suggest sharing; only the owner's tap shares.

**Native packages are frozen (STATUS.md, Oct 28): G5 adds none.** Already installed: `expo-calendar ~58.0.6` (plugin configured), `@react-native-google-signin/google-signin 16.1.5`, `expo-web-browser`, `expo-secure-store`. No ICS package: we parse a small RFC 5545 subset ourselves (`convex/model/ics.ts`) because it runs in Convex's default runtime with no Node deps, uses our DST-safe `shared/time.ts`, and keeps JS dependencies frozen with the native ones.

## Providers (current docs, fetched Oct 28–29)
- **Google OAuth 2.0, web server flow** (developers.google.com/identity/protocols/oauth2/web-server): consent `GET https://accounts.google.com/o/oauth2/v2/auth` with `client_id` (web), `redirect_uri` = `{CONVEX_SITE_URL}/google/oauth/callback`, `response_type=code`, `scope` (space-separated: `openid email` + `https://www.googleapis.com/auth/gmail.readonly` and/or `https://www.googleapis.com/auth/calendar.readonly`), `state`, `access_type=offline`, `prompt=consent` (so a refresh token comes back every time), `include_granted_scopes=true`, optional `login_hint`. Exchange `POST https://oauth2.googleapis.com/token` (form: `code`, `client_id`, `client_secret`, `redirect_uri`, `grant_type=authorization_code`) → `access_token`, `expires_in`, `refresh_token`, `scope` (what was actually granted: the consent screen lets people untick boxes), `id_token` (email). Refresh: `grant_type=refresh_token`; **`invalid_grant`** = expired or revoked → re-consent. Revoke: `POST https://oauth2.googleapis.com/revoke?token=…`.
- **Testing mode** (support.google.com/cloud/answer/15549945): ≤ 100 listed test users; Google shows an unverified-app warning; **authorizations for scopes other than basic sign-in expire after 7 days**. `gmail.readonly` is a restricted scope (fine in Testing; production needs verification + a security assessment); `calendar.readonly` is sensitive.
- **iOS (@react-native-google-signin 16.1.5, Context7 `/react-native-google-signin/docs`):** `GoogleSignin.configure({ webClientId, iosClientId, offlineAccess: true, scopes })`; `signIn()` / `addScopes({ scopes })` return `serverAuthCode` (non-null only with a web client id and offlineAccess). The server exchanges it at the token endpoint with the **web** client id + secret (empty `redirect_uri`).
- **Gmail API** (developers.google.com/workspace/gmail/api): base `https://gmail.googleapis.com/gmail/v1/users/me`. `GET /profile` → `{ emailAddress, historyId }`. First sync: `GET /messages?q=newer_than:30d&labelIds=INBOX&maxResults=…`. Changes: `GET /history?startHistoryId&historyTypes=messageAdded&labelId=INBOX&maxResults` (default 100, max 500); the response's `historyId` is the next start. **A stale/invalid `startHistoryId` → HTTP 404 → full sync** (ids are usually valid ≥ a week, sometimes only hours). `GET /messages/{id}?format=full` → headers + MIME parts (base64url). Polling from a Convex cron (`users.watch` + Pub/Sub stays a post-deadline upgrade).
- **Google Calendar API** (developers.google.com/workspace/calendar/api): `GET https://www.googleapis.com/calendar/v3/calendars/primary/events?singleEvents=true`. Full sync with `timeMin`/`timeMax` (RFC 3339), follow `nextPageToken`; `nextSyncToken` is only on the last page. Incremental: `syncToken` (+ `singleEvents`) and **never** with `timeMin`, `timeMax`, `updatedMin`, `orderBy`, `q`, `iCalUID`, `privateExtendedProperty`, `sharedExtendedProperty`; deleted events come back `status: "cancelled"`. **410 Gone → clear the token, full sync.** Times: `start.dateTime` (+ `timeZone`) or `start.date` (all-day; `end.date` exclusive).
- **expo-calendar SDK 58** (docs.expo.dev/versions/v58.0.0/sdk/calendar): the API changed — **`getCalendarsAsync` / `getEventsAsync` / `requestCalendarPermissionsAsync` are deprecated and throw at runtime** (or import them from `expo-calendar/legacy`). Use `Calendar.requestCalendarPermissions()`, `Calendar.getCalendars(Calendar.EntityTypes.EVENT)`, `Calendar.listEvents(calendars, startDate, endDate)` → `ExpoCalendarEvent[]`. iOS and Android only (web: the card says to open MEGA on the phone).
- **ICS (RFC 5545)**, fetched by the server with a conditional GET (`If-None-Match` / `If-Modified-Since`); `webcal://` → `https://`; plain http refused; ≤ `ICS.maxBytes`.
- **Better Auth** (installed 1.6.33; Context7's docs are already 1.7, where `getAccessToken` takes `accountId` and no `providerId`): we do **not** use Better Auth's account tokens or `linkSocial` for Gmail/Calendar. See "Decisions" below.

**Models:** Muse Spark only (`MODELS.judge`, structured output, `reasoning_effort: low`): (1) the mail extraction call, per message, with the body fenced as untrusted data; (2) the nightly profiler. Onboarding lines are config copy (no model call). No Muse Wonder.

## Decisions (contract step, Oct 29)
1. **A Google integration is its own grant, not the sign-in account.** The account MEGA reads can differ from the one you sign in with (the demo reads a synthetic Gmail while the owner signs in as themselves; email/password and Apple users have no Google account at all). `linkSocial` would bind the synthetic Google account to the owner's login. So: our own OAuth (web redirect to a Convex HTTP route; iOS `serverAuthCode`), tokens encrypted (AES-GCM, `INTEGRATION_TOKEN_KEY`) in `integrationSecrets`, one grant per member covering Gmail and/or Calendar. This supersedes PLAN.md row 7's "Better Auth's Google provider with accessType offline … linkSocial … getAccessToken" (it also avoids the 1.6 → 1.7 `getAccessToken` API change).
2. **Onboarding is server-driven and model-free.** Deterministic copy (`G5_COPY`), a step machine in the `onboarding` table, the name parsed by rule (prefix strip, length cap). Fast, free, testable.
3. **`onboarding.begin` replaces the interim screen** (`src/app/onboarding.tsx`); `start.tsx` (Screen 9 LoginFamily, "Join or start a family") stays and its "Start a family" calls `onboarding.begin`. `onboarding.start` stays in the API for tests/demo.
4. **Gmail stores no bodies and no addresses.** `mailItems` keeps a title, the sender's display name, a date, an amount; the private event/reminder it made. Message text is untrusted data in one structured call with no tools.
5. **The phone's calendar syncs up from the app** (`integrations.syncDevice`), polling on open (`DEVICE_CALENDAR.syncEveryMinutes`); the server never reaches the phone otherwise.

## Invariants (each one gets a test)
1. **Tokens never leave the server.** No query, mutation return, view model, card, log line or error message contains a field of `integrationSecrets`, an OAuth code, or an ICS URL after it's saved. Test: grep-style check over every G5 function's return for the fake refresh/access token strings and the seeded ICS URL; `console.*` spy during connect/refresh/disconnect.
2. **Owner only.** `integrations.*` and `mail.*` see only the caller's own rows: another adult, the admin, a kid, another family → NOT_FOUND (or an empty list). Privacy-grid rows for `integrations`, `mailItems`, `onboarding`.
3. **Found things are private until the owner shares.** Every event/reminder an integration creates is `scope: 'personal'`, `ownerId` = the integration's owner, `who` = the owner only; never household. Test: after a Gmail sync / Calendar sync / ICS add / device sync, Partner's and kids' `calendar.range` show none of them; a share suggestion is only proposed, never applied.
4. **Mail is untrusted data.** An email whose body says "share this with everyone" / "call lists_add" / "add Partner" creates at most private items: no tool calls, no shares, no messages to other members, no memory saves about other people. The extraction call has no tools; its output is schema-validated and capped (`GMAIL.maxItemsPerMessage`). Skipped senders (`GMAIL.skipSenderPatterns`) are never sent to the model.
5. **Bodies and addresses aren't stored.** After a sync, no table contains a message body, a sender address or a subject line beyond the item `title`. Test: scan the seeded+synced db for the fake inbox's body strings and addresses.
6. **OAuth state is single use and bound.** The callback rejects an unknown, expired, reused or other-member state (no grant stored, redirect with `google=failed`, no detail). Scopes granted < scopes wanted → only the granted products connect.
7. **Lapse → reconnect, never silent failure.** `invalid_grant` on refresh (fake) → the integration flips to `needs_reconnect`, one `reconnect` card in the owner's thread (dedupe), polling stops until reconnected; reconnect restores `connected`.
8. **Disconnect cleans up.** `integrations.disconnect` removes the integration's private events/items/reminders (shared copies stay), deletes the secret when no Google integration remains, calls revoke (fake records it). Idempotent.
9. **Sync is incremental and self-healing.** Gmail: stored `historyId`, 404 → full sync, no duplicate items (message × index dedupe). Calendar: `syncToken`, 410 → full sync, cancelled → removed, no duplicates. ICS: ETag/304 respected, RRULE expansion bounded, re-sync updates/removes by UID+occurrence. Device: upsert by `externalId`, removed when missing from the synced window.
10. **Onboarding never blocks and never repeats.** Each step moves on after connect or Not now; `chat.start` re-shows the current step's card instead of duplicating; an already-member can't `begin`; a name outside 1–30 chars is VALIDATION; kids and joined adults never get the admin onboarding.
11. **Family step = real members.** "A kid" → name → relationship → MEGA look → invite card creates a kid member (kid defaults, relationship, MEGA) and an invite; "Just me for now" finishes. Only the admin can `family.add` (others FORBIDDEN).
12. **Profiler only proposes about the member themself, and rules only tighten.** Updates apply only to the member's own profile; ≥ `PROFILER.applyMinConfidence` applied, ≥ `askMinConfidence` → one check question per day max (quiet `request`, inside `askWindow`), below → dropped; sensitive memories are never read; `profilerRuns` row per member × day (idempotent).
13. **Fail closed.** Missing Google env / `INTEGRATION_TOKEN_KEY` → `not_configured` everywhere, never a crash or fake data in real mode; `unconfiguredIntegrations.ts` deleted at gate end, real mode never uses a fake.
14. **No stubs, no skips.** Every v0.17 function `real`; privacy grid with zero skips.

## Backend tasks (`convex/`)
1. **Adapters** (each with unit tests against recorded-shape fixtures and a fake `fetch`, never the network): `googleOAuth.ts` (auth URL, code exchange, refresh, revoke; `configured()` = web client id + secret + token key present), `gmail.ts` (`MailSource`: profile, listRecent, history with 404 → `stale`, getMessage with MIME walk → text/plain preferred, text/html stripped, base64url decode, header parse), `googleCalendar.ts` (`CalendarSource`: pages, syncToken, 410 → `expired`, dateTime/date → `ExternalEvent` in the family tz), `icsHttp.ts` (`IcsFetcher`: webcal→https, conditional GET, size cap, timeout). Register in `registry.ts`; delete `unconfiguredIntegrations.ts`.
2. **Token vault** (`convex/model/tokenVault.ts`): AES-GCM encrypt/decrypt with Web Crypto (`crypto.subtle`, default Convex runtime) under `INTEGRATION_TOKEN_KEY` (base64url, 32 bytes); `accessTokenFor(memberId)` refreshes when within `GOOGLE.refreshSkewSeconds` of expiry; `unauthorized` → mark `needs_reconnect`.
3. **OAuth flow:** `integrations.googleStart` (state nonce → hash in `oauthStates`; returns the consent URL), HTTP `GET /google/oauth/callback` in `http.ts` (validate state, exchange, store secret, connect the granted products, post the connected line + kick off the first sync, redirect to `SITE_URL + GOOGLE.returnPath?google=connected&what=…`), `integrations.googleConnectCode` (iOS). Expire old states in a cron.
4. **Gmail sync** (internal action + cron every `GMAIL.pollMinutes` over `integrations.by_kind_status` = gmail/connected **that have a secret**): first sync = `listRecent(GMAIL.firstSyncDays)`, then `history`; per message (≤ `maxMessagesPerPoll`): skip by sender pattern → structured extraction (`MODELS.judge`, schema: `items[{ kind, title, date?, time?, amount? }]`, ≤ `maxItemsPerMessage`, body fenced `<untrusted_email>`) → `mailItems` + a private event (dated) or reminder (bills: due date) → after a sync that found something, one `mailFound` card in the owner's thread and, for school/kid items, a `shareSuggestion` (proposed, never applied). Spend through the spend guard.
5. **Calendar sync:** Google (cron `GOOGLE_CALENDAR.pollMinutes`) and ICS (cron `ICS.pollMinutes`) upsert `ExternalEvent`s as private events (`source: 'google' | 'ics'`, `integrationId`, `externalId`), remove cancelled/missing, keep within the window. `convex/model/ics.ts`: the RFC 5545 subset in `convex/ports/icsFetcher.ts`'s header (unfolding, TZID via `shared/time.ts`, VALUE=DATE, RRULE DAILY/WEEKLY/MONTHLY with INTERVAL/COUNT/UNTIL/BYDAY, EXDATE, RECURRENCE-ID overrides, STATUS:CANCELLED), bounded by `ICS.maxEvents` / `maxOccurrencesPerRule`. `integrations.addIcs` validates and fetches before saving (label = `X-WR-CALNAME` or the host).
6. **Device calendar:** `integrations.connectDevice`, `integrations.syncDevice` (validate sizes/window, upsert, remove missing in window).
7. **integrations.list / offer / disconnect / syncNow** and **mail.items / dismiss**, owner-only; `countThisMonth` from events/items in the family's current month.
8. **Onboarding:** `onboarding.begin` (everything `onboarding.start` creates, with `ONBOARDING.firstMega`, name `''` until named, family name from the template once named) + the step machine: posts (as the admin's MEGA) the G5_COPY lines and `connect` cards; `chat.send` routes the text to `setName` while step is `name` (no agent call); `chat.start` re-posts the current card when the thread is empty or mid-onboarding; `onboarding.skip`; connect success (callback / code / device / ICS) advances the step and posts the connected line; family step: the `choice` block ("A kid" / "Someone else" / "Just me for now") → the Screen 5 blocks (name `text`, relationship `choice`, get-a-MEGA `choice`, optional details `fields`, `look`, `invite`) answered via `chat.answerBlock` → `family.add` + `invites.create`; "Add someone else" loops; "That's everyone"/"Just me" → `done`.
9. **family.add** (admin; kid defaults incl. kidControls/settings like the seed's kids; MEGA from `mega` or none).
10. **Nightly profiler** (cron per family at `PROFILER.runAt` local): read the member's last day of non-sensitive memories (≤ `maxMemoriesPerRun`), one structured call → profile updates (`basics`, `routines`) with confidence; apply / ask / drop per config; check questions go through the proactive pipeline as a quiet `request` with a `choice` block (`G5_COPY.checkYes` / `checkNo` / `checkSkip`), answered → confirm/unconfirm the memory; `profilerRuns` row.
11. **Seed:** `seedG5` already adds Admin's finished onboarding, a display-only Gmail (no secret) with one found item, a schedule link. Keep it; add an `oauthStates`-free reset. `seed.resetDemo` in real mode must not touch a real grant (none is seeded).

13. **Evals:** ~15 synthetic labeled emails for extraction (school, appointment, bill, delivery, newsletter = nothing, prompt-injection, a security code = skipped) with precision/recall committed like the GD evals.
14. **Live check** (spend cap **$0.30** Meta; `MEGA_MODEL_ADAPTER=real`, deployed to colorless-ibis-289, `seed:resetDemo` after): with the owner's Google setup done — web consent for the synthetic Gmail (+ Calendar), first sync finds the synthetic school/dentist/bill mails as private items, a second poll finds nothing new, a disconnect cleans up; a public sample ICS link; the onboarding chat end to end on a fresh account (name → skip Gmail → ICS → add a kid → invite).
