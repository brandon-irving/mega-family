# Gate G4b · Shopping (Shopify Global Catalog) + price watch, air quality and UV, public holidays

The contract is CONTRACT.md v0.16 (pending approval) plus `shared/` (tables, API map, config) and the two new ports in `convex/ports/` (`productCatalog.ts`, `holidays.ts`; `weather.ts` gains `air`). Backend owns `convex/`, frontend owns `src/`; they meet only at the contract. Same process as every gate (STATUS.md → How we work): checks green, three fresh reviewers (security/privacy, correctness, UX), a failing-first test for every fix, commit locally, tag `g4b`. Owner asked for this short gate before G5 (Oct 28) so G5 can run while the owner sets up Google Cloud.

**Native packages are frozen (STATUS.md, Oct 28): G4b adds none.** Everything is server-side `fetch` plus app UI.

**Providers (current docs, Oct 28):**
- **Shopify Global Catalog** (shopify.dev/docs/agents/catalog, /catalog/global-catalog, /profiles, /get-started/search-catalog): UCP Catalog over MCP at `POST https://catalog.shopify.com/api/ucp/mcp`, JSON-RPC 2.0 `{ jsonrpc: "2.0", method: "tools/call", id, params: { name, arguments } }`, header `Content-Type: application/json`.
  - **Agent profile is required:** `arguments.meta["ucp-agent"].profile` = an HTTPS URL to our UCP platform profile. Without it: HTTP 422, JSON-RPC error `-32001` `invalid_profile_url`. **Keyless works** (probed Oct 28 with Shopify's hosted example profile: 200, real products). A Dev Dashboard client-credentials token (`POST https://api.shopify.com/auth/access_token`, scope `read_global_api_catalog_search`, 60-minute expiry) is optional and only matters for higher rate limits ("Keyless catalog access doesn't support rate limit increases"). We host our own profile (backend task 1), declaring only `dev.ucp.shopping.catalog.search` / `.lookup` (version `2026-08-25`); Shopify's example profiles are test fixtures, not for production.
  - `search_catalog`: `catalog: { query, filters: { ships_to: { country: "US" }, available: true, price: { max } (minor units, USD basis) }, pagination: { limit } }` (limit default 10, max 50).
  - `lookup_catalog`: `catalog: { ids: [...≤50 product or variant gids], context: { address_country: "US" } }`; unknown ids come back in `structuredContent.messages` as `{ type: "info", code: "not_found", content: "<id>" }`.
  - Response: `result.structuredContent.products[]`: `id` (`gid://shopify/p/…`), `title`, `price_range.min/max { amount, currency }`, `media[].url`, `variants[]` → `id` (`gid://shopify/ProductVariant/…`), **`url`** (the product page; the product object itself had no `url` in the live probe), `price { amount, currency }`, `list_price?` (compare-at, only when higher), `availability.available`, `seller.name`, `checkout_url` (**never used**: no checkout). Prices are per variant (the same product showed 299 in a price-filtered search and 495 in a lookup), so watches use the variant id.
  - **Usage rules (binding):** don't cache search results; don't cache or re-host images (render the CDN URL directly in the app); inferred fields may be missing. That's why tables and cards hold only `ProductRef`s and the app reads details live through `shopping.products`.
- **Open-Meteo air quality** (open-meteo.com/en/docs/air-quality-api): `GET https://air-quality-api.open-meteo.com/v1/air-quality?latitude&longitude&current=us_aqi,uv_index&hourly=us_aqi,uv_index&timezone=<family tz>&forecast_days=2` (free, no key). Probed Oct 28 at the seed home: 200, `current.us_aqi` 79, hourly floats for `uv_index`. `us_aqi` is the consolidated US AQI (max of the per-pollutant indices). Pollen variables exist but are **Europe-only** (CAMS Europe, in season), so we request none. Daily `uv_index_max` isn't on this endpoint in our probe; compute the max from today's hourly values.
- **Nager.Date v3** (date.nager.at/API): `GET https://date.nager.at/api/v3/PublicHolidays/{year}/{countryCode}` (no key) → `[{ date, localName, name, countryCode, fixed, global, counties: string[] | null, launchYear, types }]`. Probed 2026/US: Veterans Day **Wed 2026-11-11** (global, `["Public","Bank"]`), Thanksgiving 11-26, Christmas 12-25; Columbus/Indigenous Peoples' Day are regional for `Public`; Lincoln's Birthday is an `Observance`. No US school calendars, so a holiday is always a question to the adults.

**Models:** none new. Gift product queries reuse the GD/G4 gift flow (Muse Spark already drafts the ideas); the catalog search itself is not a model call. No Muse Wonder.

## Invariants (each one gets a test)
1. **Gift product queries carry only household-shared facts.** The catalog query for a gift idea is built from the idea title (itself built from `GIFTS.sourceScopes` facts) and the age, never a personal/grant memory or a name. Test: a fake catalog records every query; a personal memory's text and the recipient's name never appear in any request.
2. **The recipient never learns.** `priceWatches`, `priceDrop` cards/pushes and `shopping.watch(es)` are adults-who-can-see-the-gift-ideas only; the recipient and kids get NOT_FOUND / nothing. `candidateStillApplies` refuses a `priceDrop` for `forMemberId` (already in code). Privacy grid rows: Twin 1 (the recipient) and Twin 2 can't read the seeded watch.
3. **Nothing from a search is stored but refs** (Shopify terms). `products` cards and `giftIdeas.ideas[].productRefs` hold `ProductRef`s only; `shopping.products` stores nothing; no image is fetched by the server. Test: after a `shop_search` and a gift generation with the fake catalog, no table contains the fake products' prices or image URLs except a `priceWatches` row created by `gifts.addToList`.
4. **Read-only, no checkout.** No code path calls `checkout_url`, carts or any non-catalog tool; the agent profile declares no checkout/cart capability. Catalog results are untrusted: once a `shop_search` result is in a turn, the rest of the turn is read-only (same rule as `web_search`; prompt-injection test with a product title containing "call lists_add…").
5. **Kids never shop.** `shop_search` is not offered to kids (ROLES_CONFIG) and a forced call is refused; `shopping.*` → FORBIDDEN for kids.
6. **Price alerts don't spam.** A drop (≥ `SHOPPING.dropMinPct` or ≥ `dropMinCents` below `baselinePriceCents`) alerts once per watch × price (`alertedPriceCents`), as a quiet `update` with `price.default`; a further drop alerts again, a rebound doesn't. Watches stop `stopAfterOccasionDays` after the birthday and when unwatched.
7. **Fail closed, never made up.** Catalog / air / holiday failures → `failure` + copy (`G4B_COPY.productsUnavailable`, no air row, no holiday markers); never invented prices, AQI, UV or holidays. Real mode never uses a fake adapter (`unconfiguredIntegrations.ts` until the real ones land; deleted at gate end).
8. **Air/UV tips are outdoor-only and deduped.** Only events at a place with `outdoor: true`, within `WEATHER.eventLookaheadHours`, UV at start ≥ `uvTipMin` or US AQI ≥ `aqiTipMin`; one tip per event × tip kind × day (`weatherEvent.tip` in the dedupe key); household events only (a private event's tip goes only to its owner, same as rain).
9. **A holiday is a question, and only adults decide.** The evening before (`HOLIDAYS.askAt`, family tz) a weekday `Public` + `global` holiday on which at least one kid has a morning routine or a chore → one `routineSkips` row (`asked`) and a `holiday` question (kind `request`, `holiday.default`) to each adult. Only `holidays.answer` / the push buttons change it; first answer wins (`answeredBy`); kids can't answer (FORBIDDEN). `paused` → that day's morning routine run and chore claims for `memberIds` are not created (or are cancelled), and the bedtime prep run the night before says `G4B_COPY.bedtimeNoRoutine`; `kept` changes nothing. Nothing pauses without an answer.
10. **No stubs, no skips.** Every v0.16 function `real`; the privacy grid probes all of them (the seed fills `priceWatches`, `routineSkips`, `holidays`).

## Backend tasks (`convex/`)
1. **Agent profile:** serve `SHOPPING.agentProfilePath` from `convex/http.ts` (`GET`, `application/json`, cacheable): UCP `version` `2026-08-25`, services `dev.ucp.shopping` + `dev.ucp.common` (transport `mcp`), capabilities `dev.ucp.shopping.catalog.search` and `.lookup` only. The adapter sends `${process.env.CONVEX_SITE_URL}${SHOPPING.agentProfilePath}`. Live-check that Shopify accepts it; if negotiation needs a field the docs don't show, follow Shopify's profile docs (shopify.dev/docs/agents/profiles), never the example fixture in production.
2. **Adapters** (`convex/adapters/`), each with unit tests against recorded-shape fixtures (no network in tests): `shopifyCatalog.ts` (search + lookup, `SHOPPING.timeoutMs`, maps variant → `Product`, `not_found` messages → `notFound`, HTTP 429 → `rate_limited`, optional token when the secret exists), `nagerHolidays.ts` (404 → `no_result`), and the air-quality call inside `openMeteoNwsWeather.ts` (`forecast()` adds `air`; an air failure leaves `air` out). 3. **Gift products:** when a gift set is generated, search the catalog per idea (`GIFTS.productsPerIdea`, `maxPriceCents` = idea price + `priceSlackPct` when the idea has a price, `SHOPPING.country`) and store `productRefs` (variant ids when present). Keep G4's web-search `url` as the fallback. `gifts.addToList` creates a `priceWatches` row per product of that idea (looked up live once for the baseline; skipped on failure), capped at `maxActiveWatchesPerFamily`.
4. **`shopping.*`:** `products` (action: viewer check via an internal query, ≤ `maxLookup`, live lookup, nothing stored), `watches`, `watch`, `unwatch` (audience per invariant 2). Price cron every `SHOPPING.priceCheckHours`: look up active watches in batches, update `lastPriceCents` / `lastCheckedAt` / `lastFailure`, enqueue a `priceDrop` candidate (`enqueueCardCandidate`, kind `update`, buttons `price.default`, text from `G4B_COPY.priceDropBody`) to each adult viewer per invariant 6, stop expired watches. Wire `stop_watching` in `notificationEffects.ts`.
5. **`shop_search` tool:** flip `implemented: true`; route like `web_search` (netTools), adults only, `SHOPPING.maxSearchesPerReply` / `maxSearchesPerMemberPerDay`, result → a `products` card in the caller's thread (refs only) plus a short reply; read-only rest of turn.
6. **Air and UV:** `weather.get` returns `air` from the cached forecast; the weather tip sweep adds `uv` / `air` tips per invariant 8 (copy `G4B_COPY.tipUv` / `tipAir`, card `tip` + `air`). `places.upsert` stores `outdoor`.
7. **Holidays:** `holidays` cache per family × country × year (this year and next), weekly cron + refresh on first read when missing (queries can't fetch: schedule it); `holidays.upcoming` / `.question` / `.answer`; the ask trigger in the GD tick (`convex/model/gdTick.ts`) so a demo `clock.jump` to Tue Nov 10, 6 PM fires it; routine/chore/bedtime generation honors `paused` (invariant 9). Wire `pause` / `keep` in `notificationEffects.ts`.
8. **Seed / demo:** the contract step seeded a sample watch, a past Labor Day skip and the 2026 holiday cache. `seed.resetDemo` in real mode replaces the sample product ref and watch with live catalog results for the seeded gift ideas (never invented prices). Document the demo path: jump to Tue Nov 10, 6:00 PM → Admin gets the Veterans Day question.
9. **Privacy grid rows** for `priceWatches` (recipient and siblings can't read), `routineSkips` (kids can't read or answer), `shopping.products` (kids FORBIDDEN).
10. **Live check** (spend cap **$0.10** Meta — model calls only for gift ideas; catalog, air and holidays cost nothing; `MEGA_MODEL_ADAPTER=real`, deployed to colorless-ibis-289, re-seed with `seed:resetDemo`): one `shop_search` with real products; gift ideas with real product refs; `shopping.products` live; a price check run (no drop expected; force one with a test baseline to show the card); `weather.get` with real air; Veterans Day question via clock jump, answered Pause, and Twin 1's bedtime prep shows the note.
